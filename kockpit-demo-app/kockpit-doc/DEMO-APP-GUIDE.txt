                            1. VUE D'ENSEMBLE
================================================================================

### Objectif

Creer une application Spring Boot simple qui demontre l'utilisation de
kockpit-audit-sdk pour auditer automatiquement les actions utilisateur.

### Fonctionnalites

- API REST pour gerer des produits (CRUD)
- Audit automatique de toutes les operations via @Audited
- Integration avec kockpit-backend pour stockage des audits
- Configuration multi-environnement (local, dev, prod)
- Exemples d'annotations d'audit personnalisees

### Technologies

- Spring Boot 3.4.3
- kockpit-audit-sdk 1.0.0-SNAPSHOT
- kockpit-audit-annotation 1.0.0-SNAPSHOT
- Java 17+
- Maven 3.9+
- Lombok

### Flux d'audit typique

1. Client appelle POST /api/products avec payload JSON
2. ProductController.createProduct() intercepte la requete
3. Annotation @Audited declenche l'AuditInterceptor
4. AuditInterceptor construit un AuditEvent avec:
   - Domain (demo)
   - Environment (local)
   - AppId (demo-app)
   - Action (CREATE_PRODUCT)
   - User (extraite de SecurityContext ou headers)
   - Timestamp
   - Payload (parametres de la methode)
5. AuditEventPublisher envoie l'event vers kockpit-backend
6. Kockpit-backend stocke et indexe l'audit
7. Reponse retournee au client

                        5. CAS D'USAGE IMPLEMENTES
================================================================================

### 5.1 Gestion de Produits (Products)

Operations auditees:
- CREATE_PRODUCT : Creer un nouveau produit
- UPDATE_PRODUCT : Modifier un produit existant
- DELETE_PRODUCT : Supprimer un produit
- GET_PRODUCT    : Consulter un produit
- LIST_PRODUCTS  : Lister tous les produits

Donnees auditees:
- ID du produit
- Nom du produit
- Prix
- Quantite en stock
- Utilisateur qui effectue l'action
- Timestamp


### 5.2 Gestion de Commandes (Orders)

Operations auditees:
- CREATE_ORDER   : Creer une nouvelle commande
- UPDATE_ORDER   : Modifier une commande
- CANCEL_ORDER   : Annuler une commande
- SHIP_ORDER     : Expedier une commande
- DELIVER_ORDER  : Livrer une commande

Donnees auditees:
- ID de la commande
- ID du client
- Liste des produits commandes
- Montant total
- Statut de la commande
- Changements de statut
- Utilisateur
- Timestamp


### 5.3 Scenarios de demonstration

Scenario 1: Cycle de vie d'un produit
--------------------------------------
1. POST /api/products (creation)         → Audit CREATE_PRODUCT
2. GET /api/products/{id} (consultation) → Audit GET_PRODUCT
3. PUT /api/products/{id} (modification) → Audit UPDATE_PRODUCT
4. DELETE /api/products/{id} (suppression) → Audit DELETE_PRODUCT

Resultat: 4 audits dans kockpit-backend


Scenario 2: Traitement d'une commande
--------------------------------------
1. POST /api/orders (creation)           → Audit CREATE_ORDER
2. POST /api/orders/{id}/ship (expedier) → Audit SHIP_ORDER
3. POST /api/orders/{id}/deliver (livrer) → Audit DELIVER_ORDER

Resultat: 3 audits dans kockpit-backend


Scenario 3: Annulation de commande
-----------------------------------
1. POST /api/orders (creation)           → Audit CREATE_ORDER
2. POST /api/orders/{id}/cancel (annuler) → Audit CANCEL_ORDER

Resultat: 2 audits avec raison d'annulation

### 8.1 Test du cycle complet

Script de test automatise:

#!/bin/bash
BASE_URL="http://localhost:8090/demo/api"
BACKEND_URL="http://localhost:8080/backend/api"

echo "1. Creation d'un produit..."
PRODUCT_ID=$(curl -s -X POST $BASE_URL/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Laptop","price":999.99,"stock":10}' | jq -r '.data.id')

echo "Product ID: $PRODUCT_ID"

echo "2. Consultation du produit..."
curl -s $BASE_URL/products/$PRODUCT_ID | jq

echo "3. Modification du produit..."
curl -s -X PUT $BASE_URL/products/$PRODUCT_ID \
  -H "Content-Type: application/json" \
  -d '{"name":"Laptop Pro","price":1299.99,"stock":5}' | jq

echo "4. Verification des audits..."
curl -s -u user:password \
  "$BACKEND_URL/demo/local/audits/_search?start=0&size=10" | jq

echo "5. Suppression du produit..."
curl -s -X DELETE $BASE_URL/products/$PRODUCT_ID | jq

echo "6. Verification finale des audits..."
curl -s -u user:password \
  "$BACKEND_URL/demo/local/audits/_search?start=0&size=10" | jq '.total_count'

echo "Test termine! Nombre d'audits attendus: 4"

✓ Payload contient les donnees pertinentes
✓ Timestamp correct
✓ User extrait correctement (si disponible)

================================================================================
                            10. TROUBLESHOOTING
================================================================================

### Probleme: Audits non envoyes

Symptome: L'application demarre mais aucun audit n'apparait dans kockpit-backend

Solutions:
1. Verifier que kockpit-backend est accessible
   curl -u user:password http://localhost:8080/backend/api/config

2. Verifier la configuration kockpit.audit.backend.url
   cat src/main/resources/application.yaml

3. Activer les logs debug
   logging.level.org.kockpit: DEBUG

4. Verifier que @EnableAuditing est present dans DemoApplication.java


### Probleme: Erreur 401 lors de l'envoi des audits

Symptome: Logs contiennent "401 Unauthorized" vers kockpit-backend

Solutions:
1. Verifier username/password dans application.yaml
2. Verifier que kockpit-backend a l'authentification activee
3. Tester manuellement: curl -u user:password http://localhost:8080/backend/api/config


### Probleme: Application ne demarre pas

Symptome: Erreur au demarrage concernant les dependances

Solutions:
1. Builder kockpit d'abord
   cd /home/debian/sources/kiss/kockpit
   mvn clean install -DskipTests

2. Verifier les dependances
   cd /home/debian/sources/kiss/kockpit-demo-app
   mvn dependency:tree

3. Verifier la version Java
   java -version  # Doit etre 17+


### Probleme: Audits vides ou incomplets

Symptome: Les audits sont crees mais manquent de donnees

Solutions:
1. Verifier les annotations @AuditedParam sur les parametres
2. Verifier que les objets sont serialisables (pas de references circulaires)
3. Ajouter @JsonIgnore sur les champs problematiques


### Probleme: Performance degradee

Symptome: L'application est lente

Solutions:
1. Audit asynchrone par defaut (verifier la config)
2. Augmenter le timeout: kockpit.audit.backend.timeout
3. Verifier que kockpit-backend repond rapidement
4. Considerer un circuit breaker (Resilience4j)

# Rechercher tous les audits de creation de produit
curl -u user:password \
  -X POST "http://localhost:8080/backend/api/demo/local/audits/_search" \
  -H "Content-Type: application/json" \
  -d '{
    "filters": {
      "action": "CREATE_PRODUCT"
    },
    "start": 0,
    "size": 20
  }'

# Rechercher les audits d'un utilisateur specifique
curl -u user:password \
  -X POST "http://localhost:8080/backend/api/demo/local/audits/_search" \
  -H "Content-Type: application/json" \
  -d '{
    "filters": {
      "user": "john.doe@example.com"
    },
    "start": 0,
    "size": 50
  }'
