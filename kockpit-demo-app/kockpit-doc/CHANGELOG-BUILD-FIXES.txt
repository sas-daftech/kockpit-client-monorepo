================================================================================
                              RÉSUMÉ
================================================================================

Cette mise à jour corrige les problèmes de compilation qui empêchaient le
projet de se builder correctement. Les erreurs étaient liées à:
- L'utilisation de Java 25 au lieu de Java 17
- La configuration manquante de Lombok dans Maven Compiler Plugin
- Des dépendances Lombok manquantes dans certains modules


================================================================================
                         FICHIERS MODIFIÉS
================================================================================

1. /kockpit/pom.xml
   Lignes: 25-43 (nouveau bloc)
   Type: Ajout configuration

   Ajout de la section <build><pluginManagement> avec configuration
   du maven-compiler-plugin pour activer l'annotation processing Lombok.

   Raison:
   - Le Maven Compiler Plugin 3.13.0 nécessite une configuration explicite
     des annotation processors
   - Sans cela, les annotations Lombok (@Data, @Builder, etc.) sont ignorées

   Impact:
   - Tous les modules enfants bénéficient de cette configuration
   - Lombok génère maintenant correctement les getters/setters/builders


2. /kockpit/kockpit-audit/kockpit-audit-api/pom.xml
   Lignes: 13-17
   Type: Modification scope dépendance

   Changement du scope de la dépendance lombok de "compile" à "provided".

   Avant:
   <dependency>
       <groupId>org.projectlombok</groupId>
       <artifactId>lombok</artifactId>
   </dependency>

   Après:
   <dependency>
       <groupId>org.projectlombok</groupId>
       <artifactId>lombok</artifactId>
       <scope>provided</scope>
   </dependency>

   Raison:
   - Lombok n'est nécessaire qu'à la compilation, pas au runtime
   - Réduit la taille des JARs générés
   - Bonne pratique Maven


3. /kockpit/kockpit-audit/kockpit-audit-httpexchange/pom.xml
   Lignes: 13-17 (nouveau bloc)
   Type: Ajout dépendance

   Ajout de la dépendance Lombok manquante.

   Ajouté:
   <dependency>
       <groupId>org.projectlombok</groupId>
       <artifactId>lombok</artifactId>
       <scope>provided</scope>
   </dependency>

   Raison:
   - Le code source utilise @Slf4j, @Data, @Builder
   - La dépendance n'était pas déclarée dans le pom.xml
   - Causait des erreurs "package lombok does not exist"

   Impact:
   - Le module se compile maintenant correctement
   - Les annotations Lombok sont traitées

                         PROBLÈMES RÉSOLUS
================================================================================

PROBLÈME 1: Incompatibilité Version Java
-----------------------------------------
Symptômes:
  - Fatal error compiling: java.lang.ExceptionInInitializerError
  - com.sun.tools.javac.code.TypeTag :: UNKNOWN

Cause:
  - Java 25 utilisé alors que le projet requiert Java 17
  - Lombok 1.18.36 incompatible avec Java 25

Solution appliquée:
  - Utilisation de Java 17 via JAVA_HOME
  - Documentation de la procédure correcte

Commande:
  JAVA_HOME=/path/to/java-17 mvn clean install -DskipTests

Résultat:
  ✓ Compilation réussie avec Java 17
  ✓ Lombok fonctionne correctement


PROBLÈME 2: Lombok Non Configuré pour Maven Compiler
-----------------------------------------------------
Symptômes:
  - org.kockpit.audit.api.AbstractAuditEvent is not abstract and
    does not override abstract method getEndTime()
  - Les méthodes générées par @Data ne sont pas reconnues

Cause:
  - Maven Compiler Plugin 3.13.0 ne traite pas Lombok sans configuration
  - annotationProcessorPaths manquant

Solution appliquée:
  - Ajout de la configuration dans kockpit/pom.xml
  - Configuration propagée à tous les modules via pluginManagement

Résultat:
  ✓ Lombok génère correctement les méthodes
  ✓ Les annotations @Data, @Builder, etc. fonctionnent
  ✓ AbstractAuditEvent compile sans erreur


PROBLÈME 3: Dépendances Lombok Manquantes
------------------------------------------
Symptômes:
  - package lombok does not exist
  - cannot find symbol: class Slf4j, Data, Builder

Module concerné:
  - kockpit-audit-httpexchange

Cause:
  - Le code utilise des annotations Lombok
  - La dépendance n'était pas déclarée dans le pom.xml

Solution appliquée:
  - Ajout de la dépendance avec scope=provided

Résultat:
  ✓ Le module compile correctement
  ✓ Toutes les classes utilisant Lombok fonctionnent

================================================================================
                         NOTES TECHNIQUES
================================================================================

Pourquoi Java 17?
-----------------
- Défini dans pom.xml: <maven.compiler.release>17</maven.compiler.release>
- Spring Boot 3.4.3 nécessite minimum Java 17
- Lombok 1.18.36 est testé et compatible avec Java 17
- Version LTS stable et largement utilisée

Pourquoi annotationProcessorPaths?
-----------------------------------
- Maven Compiler Plugin 3.13.0 nécessite une configuration explicite
- Les annotation processors (comme Lombok) doivent être déclarés
- Sans cela, les annotations sont ignorées silencieusement
- Permet de séparer les dépendances de compilation des dépendances runtime

Pourquoi scope=provided pour Lombok?
-------------------------------------
- Lombok transforme le bytecode à la compilation
- Les classes générées n'ont pas besoin de Lombok au runtime
- Réduit la taille des JARs finaux
- Évite les dépendances inutiles dans le classpath
