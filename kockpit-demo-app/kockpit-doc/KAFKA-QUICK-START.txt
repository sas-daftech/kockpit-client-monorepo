================================================================================
              KOCKPIT AUDIT TRAIL WITH KAFKA - QUICK START
================================================================================

Ce guide vous permet de démarrer rapidement avec Kockpit Audit Trail
utilisant Kafka pour une architecture événementielle scalable.

Date: 2025-12-23
Version: 1.0.0-SNAPSHOT

================================================================================
                           ARCHITECTURE
================================================================================

    Demo App (@Audited)
         ↓
    Kafka Producer
         ↓
    Kafka Topic: "audit"
         ↓
    Kafka Stream Consumer
         ↓
    OpensearchIndexer
         ↓
    OpenSearch
         ↓
    OpenSearch Dashboards (Visualisation)


Avantages de cette architecture:
  ✓ Asynchrone - Pas d'impact sur les performances de l'application
  ✓ Résiliente - Kafka garantit la livraison des messages
  ✓ Scalable - Peut gérer des millions d'audits
  ✓ Découplée - Applications et indexation indépendantes

================================================================================
              ÉTAPE 3: CONFIGURER LA DEMO APPLICATION
================================================================================

La demo app est déjà configurée pour envoyer les audits à Kafka.

Configuration dans application.yaml:
  spring:
    kafka:
      bootstrap-servers: localhost:9092
      producer:
        key-serializer: org.apache.kafka.common.serialization.StringSerializer
        value-serializer: org.apache.kafka.common.serialization.StringSerializer

  kockpit:
    sdk:
      domain: demo
      env: local
      appId: demo-app
      enabled: true
      service:
        audit:
          notification:
            topic: audit


Dépendances requises dans pom.xml:
  - kockpit-audit-sdk
  - kockpit-audit-annotation
  - kockpit-audit-web-starter
  - kockpit-audit-notification-starter-kafka

================================================================================
                        ARCHITECTURE DÉTAILLÉE
================================================================================

Flux d'un audit:

1. Application Demo:
   - Méthode annotée avec @Audited
   - Spring AOP intercepte l'appel
   - SDK Kockpit capture requête + réponse

2. Kafka Producer (dans Demo App):
   - SDK sérialise l'audit en JSON
   - Envoie au topic "audit" sur Kafka
   - Kafka acknowledge la réception

3. Kafka (broker):
   - Stocke le message dans le topic
   - Garantit la durabilité
   - Gère le partitionnement

4. Kafka Stream Consumer:
   - Écoute le topic "audit"
   - Consomme les messages par batch (max 50)
   - Transforme via AuditReportMapper

5. OpensearchIndexer:
   - Reçoit les audits transformés
   - Accumule dans un buffer
   - Indexe par batch toutes les 5 secondes
   - Crée/utilise l'index approprié selon domain/env/ttl

6. OpenSearch:
   - Stocke les audits indexés
   - Gère la rotation des index par jour
   - Applique le TTL (5 jours par défaut)

7. OpenSearch Dashboards:
   - Interface de visualisation
   - Requêtes en temps réel
   - Dashboards personnalisables


Gestion des erreurs:
  - Kafka: Retry automatique avec backoff
  - Stream Consumer: DLQ (Dead Letter Queue) pour messages invalides
  - OpenSearch: Retry sur échec d'indexation
  - Application: Audit envoyé en asynchrone, pas d'impact sur l'utilisateur


================================================================================
                        CONFIGURATION AVANCÉE
================================================================================

Kafka Producer (dans Demo App):
  Configuration dans application.yaml:
    spring:
      kafka:
        bootstrap-servers: localhost:9092
        producer:
          acks: 1                    # Niveau de confirmation
          retries: 3                 # Nombre de tentatives
          batch-size: 16384          # Taille du batch
          linger-ms: 10              # Délai avant envoi
          compression-type: snappy   # Compression des messages


Kafka Consumer (Stream App):
  Configuration dans application.yml:
    spring:
      kafka:
        consumer:
          group-id: kockpit-audit-stream
          max-poll-records: 50       # Nombre max par poll
          auto-offset-reset: latest  # Démarrer au dernier offset
          enable-auto-commit: false  # Commit manuel


OpensearchIndexer:
  Configuration dans application.yml:
    kockpit:
      audit:
        stream:
          opensearch:
            scheduler_ms: 5000       # Fréquence d'indexation
            endpoints: http://localhost:9200
            index_suffix: audit-data


Rotation des index:
  Format: {domain}-audit-data-{env}-ttl{ttl}d-{date}
  Exemple: demo-audit-data-local-ttl5d-2025.12.23-1

  Rotation automatique:
    - Nouvel index créé chaque jour à minuit
    - TTL appliqué automatiquement
    - Vieux index supprimés après expiration

================================================================================
                        TROUBLESHOOTING
================================================================================

Problème: Les audits n'apparaissent pas dans OpenSearch
Solution:
  1. Vérifier que Kafka est démarré:
     $ docker ps | grep kafka

  2. Vérifier que le Stream Consumer tourne:
     Voir les logs, doit afficher "Started KafkaStreamApplication"

  3. Vérifier les logs du Stream Consumer:
     Rechercher "indexing took X ms" - confirme l'indexation

  4. Vérifier les topics Kafka:
     $ docker exec -it kafka-dev kafka-topics --list \
       --bootstrap-server localhost:9092
     Doit contenir le topic "audit"

  5. Vérifier le consumer lag:
     Si lag > 0, le consumer est en retard


Problème: Demo app ne démarre pas - erreur Kafka
Solution:
  1. Vérifier que Kafka est accessible:
     $ nc -zv localhost 9092

  2. Vérifier la configuration dans application.yaml:
     spring.kafka.bootstrap-servers: localhost:9092

  3. Vérifier les dépendances Maven:
     kockpit-audit-notification-starter-kafka doit être présente


Problème: Stream Consumer ne consomme pas
Solution:
  1. Vérifier le topic dans les logs du consumer:
     Doit afficher "topics: audit"

  2. Vérifier que le topic existe dans Kafka:
     $ docker exec -it kafka-dev kafka-topics --describe \
       --topic audit --bootstrap-server localhost:9092

  3. Vérifier le consumer group:
     $ docker exec -it kafka-dev kafka-consumer-groups --list \
       --bootstrap-server localhost:9092
     Doit contenir "kockpit-audit-stream"


Problème: OpenSearch Dashboards ne montre rien
Solution:
  1. Vérifier le time range (en haut à droite)
     Mettre sur "Last 24 hours" ou "Last 7 days"

  2. Vérifier l'index pattern:
     Doit être "demo-audit-data-*"

  3. Vérifier le champ de temps:
     Utiliser "start" et non "@timestamp"

  4. Refresh l'index pattern:
     Dashboards Management → Index Patterns → Refresh


Problème: Erreur "ConfigApiService bean not found"
Solution:
  1. Vérifier les profils Maven lors du build:
     mvn spring-boot:run -P filesystem,opensearch

  2. Les profils Spring ne suffisent pas, il faut aussi les profils Maven


Problème: Port 9092 déjà utilisé
Solution:
  1. Trouver le processus:
     $ sudo lsof -i :9092

  2. Arrêter l'ancien Kafka:
     $ docker stop kafka-dev

  3. Redémarrer proprement:
     $ docker compose -f docker-compose-dev.yml down
     $ docker compose -f docker-compose-dev.yml up -d
