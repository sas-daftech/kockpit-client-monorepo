1. AUTHENTIFICATION
================================================================================

Type: HTTP Basic Authentication

Header requis:
  Authorization: Basic <base64(username:password)>

Exemple:
  # Encoder les credentials
  $ echo -n "user:password" | base64
  dXNlcjpwYXNzd29yZA==

  # Utiliser dans la requete
  Authorization: Basic dXNlcjpwYXNzd29yZA==

Avec curl:
  curl -u user:password http://localhost:8080/backend/api/...

Codes de retour:
  200 OK           - Authentification reussie
  401 Unauthorized - Credentials invalides
  403 Forbidden    - Acces refuse

2. AUDITS API
================================================================================

Base path: /{domain}/{env}/audits

Parametres path communs:
  domain : Domaine metier (ex: rcu, payment, billing)
  env    : Environnement (ex: local, dev, staging, prod)


--------------------------------------------------------------------------------
2.1 Rechercher des audits (GET)
--------------------------------------------------------------------------------

Endpoint:
  GET /{domain}/{env}/audits/_search

Parametres query:
  start : Offset de pagination (defaut: 0)
  size  : Nombre d'elements (defaut: 50, max: 1000)

Exemple de requete:
  GET /rcu/local/audits/_search?start=0&size=10

Reponse (200 OK):
  {
    "size": 10,
    "items": [
      {
        "id": "audit-123",
        "timestamp": "2025-12-01T21:00:00Z",
        "user": "john.doe",
        "action": "USER_LOGIN",
        "details": {...}
      },
      ...
    ],
    "total_count": 156
  }

Codes de retour:
  200 OK              - Succes
  400 Bad Request     - Parametres invalides
  401 Unauthorized    - Non authentifie
  500 Internal Error  - Erreur serveur


--------------------------------------------------------------------------------
2.2 Rechercher des audits (POST)
--------------------------------------------------------------------------------

Endpoint:
  POST /{domain}/{env}/audits/_search

Content-Type:
  application/json

Body:
  {
    "filters": [
      {
        "field": "user",
        "operator": "equals",
        "value": "john.doe"
      },
      {
        "field": "timestamp",
        "operator": "gte",
        "value": "2025-12-01T00:00:00Z"
      }
    ],
    "sort": {
      "field": "timestamp",
      "order": "desc"
    },
    "pagination": {
      "start": 0,
      "size": 50
    }
  }

Operateurs supportes:
  - equals      : Egalite exacte
  - contains    : Contient (texte)
  - gte         : Greater than or equal (>=)
  - lte         : Less than or equal (<=)
  - gt          : Greater than (>)
  - lt          : Less than (<)
  - in          : Dans une liste
  - not_in      : Pas dans une liste

Exemple de requete:
  POST /rcu/local/audits/_search
  Content-Type: application/json

  {
    "filters": [
      {
        "field": "action",
        "operator": "in",
        "value": ["USER_LOGIN", "USER_LOGOUT"]
      }
    ],
    "sort": {
      "field": "timestamp",
      "order": "desc"
    },
    "pagination": {
      "start": 0,
      "size": 20
    }
  }

Reponse (200 OK):
  {
    "size": 20,
    "items": [...],
    "total_count": 45
  }

4. FEATURE FLIPPING API
================================================================================

Base path: /{domain}/{env}/feature-flipping


--------------------------------------------------------------------------------
4.1 Activer/Desactiver une feature
--------------------------------------------------------------------------------

Endpoint:
  PUT /{domain}/{env}/feature-flipping?key={featureKey}

Content-Type:
  application/json

Parametres query:
  key : Identifiant de la feature

Body:
  {
    "enabled": true,
    "percentage": 100,
    "metadata": {
      "author": "john.doe",
      "reason": "Deploiement en production"
    }
  }

Champs body:
  enabled    : (boolean) Activer ou desactiver
  percentage : (int) Pourcentage de deploiement (0-100)
  metadata   : (object) Metadonnees optionnelles

Exemple de requete:
  PUT /rcu/prod/feature-flipping?key=new-payment-gateway
  Content-Type: application/json

  {
    "enabled": true,
    "percentage": 10,
    "metadata": {
      "author": "ops-team",
      "reason": "Canary deployment - 10% des utilisateurs"
    }
  }

Reponse (200 OK):
  {
    "key": "new-payment-gateway",
    "enabled": true,
    "percentage": 10,
    "domain": "rcu",
    "env": "prod",
    "updated_at": "2025-12-01T21:45:00Z",
    "metadata": {
      "author": "ops-team",
      "reason": "Canary deployment - 10% des utilisateurs"
    }
  }

Cas d'usage:
  - Canary deployment (deploiement progressif)
  - A/B testing
  - Kill switch (desactivation d'urgence)
  - Feature preview pour certains utilisateurs

6. CODES D'ERREUR
================================================================================

Format des erreurs:
  {
    "timestamp": "2025-12-01T21:30:00Z",
    "status": 404,
    "error": "Not Found",
    "message": "Audit with id 'xyz' not found",
    "path": "/backend/api/rcu/local/audits/xyz"
  }


Codes HTTP:
  200 OK                 - Succes
  201 Created            - Ressource creee
  204 No Content         - Succes sans contenu

  400 Bad Request        - Requete invalide
  401 Unauthorized       - Non authentifie
  403 Forbidden          - Acces refuse
  404 Not Found          - Ressource non trouvee
  409 Conflict           - Conflit (ex: ressource existe deja)

  500 Internal Error     - Erreur serveur
  503 Service Unavailable - Service temporairement indisponible


Messages d'erreur courants:

  400 Bad Request:
    - "Invalid parameter: size must be between 1 and 1000"
    - "Invalid date format: expected ISO-8601"
    - "Missing required field: key"

  401 Unauthorized:
    - "Authentication required"
    - "Invalid credentials"

  404 Not Found:
    - "Audit not found"
    - "Configuration not found"

  500 Internal Error:
    - "Failed to connect to OpenSearch"
    - "Database error"

7.4 Exemple: Script de monitoring
--------------------------------------------------------------------------------

Script Bash pour monitorer la sante de l'application:

#!/bin/bash
# monitor.sh

API_BASE="http://localhost:8080/backend"

echo "=== Kockpit Backend Monitoring ==="
echo ""

# Health check
echo "1. Health Check:"
curl -s "$API_BASE/actuator/health" | python3 -m json.tool
echo ""

# Disk space
echo "2. Disk Space:"
curl -s "$API_BASE/actuator/health" | \
  python3 -c "import sys,json; print(json.load(sys.stdin)['components']['diskSpace'])"
echo ""

# JVM Memory
echo "3. JVM Memory:"
curl -s "$API_BASE/actuator/metrics/jvm.memory.used" | \
  python3 -c "import sys,json; \
    data=json.load(sys.stdin); \
    value=data['measurements'][0]['value']; \
    print(f'{value/1024/1024:.2f} MB')"
echo ""

# Recent audits count
echo "4. Recent Audits:"
curl -s -u user:password "$API_BASE/api/rcu/local/audits/_search?size=1" | \
  python3 -c "import sys,json; print(json.load(sys.stdin)['total_count'])"
echo ""


Utilisation:
$ chmod +x monitor.sh
$ ./monitor.sh
